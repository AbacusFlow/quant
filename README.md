# quant — A股 ETF 动量轮动策略

一套自用的 A 股 ETF 动量轮动交易系统:每日收盘后计算目标持仓、次日开盘人工下单,配套回测引擎、账本记账、风险监控与自动生成的净值报告。

**在线报告(每日自动更新):** https://abacusflow.github.io/quant/

## 策略原理

### 核心思路:动量轮动

在 9 只覆盖不同大类资产的 ETF 里,比较「过去一段时间谁涨得最多」,持有最强者;若所有候选近期都在下跌(绝对动量为负),则退出该仓位。

**退出后钱去哪,取决于版本**:V0/V1 退出后持现金;**当前线上的 V2 目标权重里不保留策略性现金**——绝对动量滤空与波动率降仓腾出的全部空档,都会各半买入黄金 ETF(518880)与十年国债 ETF(511260)。所以 V2 不存在真正的空仓状态,「避险」是换成防御资产,而不是离场;金债本身也会亏。(实际账户仍会因整手、佣金与再平衡带宽留下少量零头现金,那是执行残差,不是策略仓位。)

| 代码 | 名称 | 类别 |
|---|---|---|
| 510300 | 沪深300ETF | A股宽基 |
| 510500 | 中证500ETF | A股中盘 |
| 512100 | 中证1000ETF | A股小盘 |
| 159915 | 创业板ETF | A股成长 |
| 513100 | 纳指ETF | 跨境 |
| 513500 | 标普500ETF | 跨境 |
| 159920 | 恒生ETF | 跨境 |
| 518880 | 黄金ETF | 商品 |
| 511260 | 十年国债ETF | 债券 |

关键执行规则:

- **无未来数据**:信号用 T 日**收盘价**计算,成交在 T+1 日**开盘价**。
- **A 股规则建模**:T+1、100 股整手、ETF 佣金万 0.5(最低 5 元)、ETF 免印花税、滑点万 5 单边。
- **不加杠杆、不做空**:各标的目标权重之和 ≤ 1,余额为现金。
- **换仓缓冲(滞回)**:新标的动量需超出当前持仓 `ROTATION_BUFFER`(当前 2%)才切换,避免排名轻微抖动就来回交易。

### 版本演进

| 版本 | 做了什么 | 解决什么问题 |
|---|---|---|
| **V0** 基线 | 纯动量轮动 | 能捕捉趋势,但大跌时回撤深 |
| **V1** +波动率目标 | 组合近期已实现波动明显高于自身历史水平时按比例降仓(余额持现金),波动回落后自动加回。自适应、无固定阈值旋钮、因果计算 | 动量策略的崩盘集中在高波动期 → 回撤显著改善,收益基本不变(赚在「稳」而非「多」) |
| **V2** +防御 sleeve | V1 降仓/滤空留下的闲置现金,按各半买入黄金 ETF + 国债 ETF,不再干躺 | 现金零收益 → 债吃利息、金在股票熊年(2018/2022)提供正贡献。运行时无动态参数,但 50/50 这个规则是在全债 / 全金 / 择优 / 各半四种方案里按历史表现挑出来的(`scripts/experiment_sleeve.py`),存在选择偏差 |

### 当前线上配置与三版本对比

模式 `ensemble`(15/20/25 三个回看周期各自选最强再平均,权重会出现 1/3、2/3 等分数)+ 波动率目标 + 防御 sleeve + 换仓缓冲 2%,即下表的 V2。

下表三行为**同一口径**:2017-08-24 ~ 2026-08-12(2171 个交易日,起点受十年国债 ETF 上市日限制)、18.5 万本金、`buffer=2%`、前复权、**固定费用模型**(ETF 佣金万 0.5 最低 5 元、滑点万 5 单边、100 股整手、ETF 免印花税),数据指纹 `74759aec21f256ec`。样本外自 2022-01-01 起。

| 版本 | 年化 | 夏普 | 最大回撤 | 样本外年化 | 样本外夏普 | 样本外回撤 |
|---|---|---|---|---|---|---|
| V0 基线 ensemble | 17.65% | 0.77 | -25.5% | 27.92% | 1.05 | -25.5% |
| V1 +波动率目标 | 18.00% | 1.01 | -18.2% | 29.19% | 1.43 | -17.8% |
| **V2 +防御 sleeve(当前)** | **19.97%** | **1.07** | **-17.9%** | **33.33%** | **1.53** | **-16.6%** |

「固定费用模型」不等于真实成交成本:引擎假设每笔委托都能在次日开盘价 ±万 5 全额成交,没有建模停牌、涨跌停、买卖价差、成交量与冲击成本。

整张表由 `scripts/experiment_variants.py` 一次性生成(强制 `qfq_only=True`、不写缓存、先打印数据指纹);复现时请先核对指纹再比对数字。

样本外三列的区间切法沿用 `scripts/experiment_buffer.py`:把 2021 年最后一个交易日作为基准点纳入(否则会漏掉 2022-01-04 当日收益)。`run_rotation.py` 直接切 `2022-01-01` 之后,同一条净值曲线会打印 33.23% / 1.52 / −16.61%。差异只来自这一天的基准点,不是不同的回测。

## 已知局限(重要)

把上面那些数字直接当成预期收益是错的。以下都是自查后确认存在的问题:

1. **回看周期 20 天是敏感性扫描的尖峰**,不是平台。15 天和 25 天在全区间表现差不少。用 `ensemble`(多周期平均)正是为了对冲这个尖峰,但没有消除它。
2. **「样本外」已经不独立了**。`OOS_SPLIT=2022-01-01` 虽然与初版参数同时写入,但此后 V1、V2、buffer 以及多轮研究都反复在这同一段数据上做检验,它早已被反复使用消耗掉。样本外数字漂亮(33%)不能当作独立验证。
3. **走查(walk-forward)检验给出的数字低得多**。滚动窗口只用过去数据选回看周期,在 2020-10~2026-06、1 万本金的口径下多数配置年化 17~21%(最差的「2 年窗口 + 每年调参」只有 3.4%),而固定 20 天是 28.1%。这只能说明「按那套规则动态选参会更差」,不能反推固定 20 天的超额全部来自过拟合;但它至少说明这个策略的表现对选参方式高度敏感,把 20~33% 当预期是不合适的。该实验跑的是 `single + buffer=1% + 无 V1/V2`,与当前线上配置不同,数字不可直接套用。(脚本:`scripts/experiment_walkforward.py`)
4. **回测的「可成交性」没有建模**。前复权价是合成价格序列且会随分红重新锚定,历史上的整手股数、最低佣金占比都是用今天的复权价倒推的,与当年真实成交并不一致;引擎又假设每笔委托必然在次日开盘价 ±万 5 全额成交,不含停牌、涨跌停、价差、成交量与冲击成本。这些简化**总体上可能使回测结果偏乐观**。
5. **标的池本身是事后挑的**。这 9 只 ETF、两层覆盖层(波动率目标 / 防御 sleeve)、以及 sleeve 的金债 50/50 分法,都是在观察同一段历史之后选定的。这类选择不会出现在任何单一参数的敏感性扫描里,但同样是过拟合来源。
6. **回测窗口只有 9 年**(2017-08 起,受十年国债 ETF 上市日限制),且 2022 年之后是对本策略的顺风窗口。没有覆盖足够多的完整牛熊周期。
7. **样本量小**:9 只 ETF、每日 top-1(ensemble 下约 1~3 只),分散度有限;单一标的的行情特性会显著影响结果。
8. **小资金下费用占比高**。5 元最低佣金在 1 万本金下会明显拖累年化,所以作者的部署惯例是 10 万以下用 `single` 模式(整仓切换、摊薄最低佣金)、10 万以上才用 `ensemble`——这是人工选择,代码里没有这条自动切换规则。
9. **人工执行会偏离信号**。真实记录里出现过延后执行、只做部分腿、以及至少一次拒绝卖出的情况,实盘表现因此与回测存在偏差。

参数改动的纪律:任何参数调整必须有回测背书、必须做抗过拟合检验(走查 / 参数族 / 滚动窗口 / bootstrap),并把结论(包括对该改动**不利**的证据)写进 `research/` 存档。示例见 [`research/2026-08-13-rotation-buffer.md`](research/2026-08-13-rotation-buffer.md)。

## 代码结构

```
data.py → strategy.py → backtest.py (单标的)  → metrics.py / report.py
                      ↘ portfolio.py (多标的) ↗      (run_rotation.py)
```

| 文件 | 职责 |
|---|---|
| `data.py` | akshare 取日线(前复权),东财 → 腾讯 → 新浪三源容错(新浪是不复权源,货币路径 `qfq_only=True` 下只用前两源),CSV 缓存并内置「名新实旧」缓存投毒防线 |
| `strategy.py` | 动量轮动 / ensemble / 回撤控制 / 波动率目标 / 防御 sleeve,全部保持因果(T 日系数只用 ≤T 数据) |
| `portfolio.py` | 多标的组合引擎:目标权重进,T+1 开盘成交,整手、费用、按比例分配现金预算、再平衡带宽 |
| `backtest.py` | 单标的双均线演示引擎 |
| `metrics.py` | 年化/夏普/最大回撤/胜率 |
| `run_rotation.py` | 轮动回测 CLI(全期 / 样本内 / 样本外、敏感性扫描、变体对比) |
| `daily_signal.py` | 每日信号与调仓建议:按真实账本资产定股数、现金封顶、再平衡带宽过滤,写 `output/signal_log.csv` |
| `record_trade.py` | 记录成交/入金/出金到 `output/executions.csv`,写前回放校验(负现金/负持仓即拒绝) |
| `check_prices.py` | 开盘前用独立数据源校验昨收,防缓存过期 |
| `check_risk.py` | 实盘回撤监控,超过回测最大回撤倍数时告警 |
| `report_web.py` | 生成自包含的静态报告页(实盘 vs 模拟、持仓 vs 目标、策略演进) |
| `scripts/` | 本地 cron 编排、Telegram 推送、研究实验脚本(`experiment_variants.py` = 上表三版本对比的复现入口;`experiment_buffer*.py` = 换仓缓冲研究) |
| `research/` | 参数决策的研究报告存档(含可复现脚本与数据指纹) |

设计上的两条硬约束:

- **账本 fail-closed**:账本解析失败、负现金、负持仓、非法数值一律让信号运行失败退出,绝不静默降级。
- **复权口径不混用**:货币路径(`daily_signal` / `check_risk`)开启 `qfq_only=True`,宁可当日无信号,也不接受新浪的不复权数据回退。

## 运行

本地不装依赖,一切走 Docker:

```bash
docker build -f .docker/Dockerfile -t quant .
R="docker run --rm --network=host -v $PWD:/work quant python"

# 复现「三版本对比」整张表(V0/V1/V2 同一口径,打印数据指纹)
$R scripts/experiment_variants.py --capital 185000 --end 2026-08-12

# 单跑 V2(当前线上配置)。覆盖层默认关闭,必须显式打开
$R run_rotation.py --mode ensemble --capital 185000 --vol-target --sleeve --end 2026-08-12

# 回看周期敏感性扫描 / 变体对比
$R run_rotation.py --sensitivity
$R run_rotation.py --compare

# 每日信号(开盘前跑,用昨收)
$R daily_signal.py --mode ensemble --capital 185000 --vol-target --sleeve

# 生成报告页
$R report_web.py --mode ensemble --capital 185000 --vol-target --sleeve
```

**注意:代码里的默认值不是线上配置。** `config.py` 的 `VOL_TARGET_ENABLED` / `SLEEVE_ENABLED` 都是 `False`;`daily_signal.py` / `report_web.py` / `check_risk.py` 的 `--mode` 默认 `single`,`report_web.py` / `check_risk.py` 的 `--capital` 默认 1 万,而 `daily_signal.py --capital` 默认是 `None`——它优先用账本回放出的真实资产,`--capital` 只在账本回放不出资产时兜底。作者线上跑的 V2 来自未入库的 `.env`(见 `.env.example`),由 `scripts/daily_local.sh` 读出后传给这些脚本。不传上面那几个 flag 跑出来的就不是 V2。

`daily_signal.py` 不是只读命令:它会写 `output/signal_log.csv`,并可能改写 `output/executions.csv` 里的计划行(同一信号日幂等)。只想看数字不想动账本的话,跑 `run_rotation.py` 或 `scripts/experiment_variants.py`。

akshare 取数需要联网(本机部署用 `--network=host`);有缓存时可离线运行。

## 自动化

全部跑在本机 cron,不依赖 GitHub Actions:

- **交易日 08:03** — 计算信号、校验昨收、回撤检查,通过 Telegram 推送今日调仓指令,提交信号日志。
- **交易日 17:03** — 账户小结与持仓偏离推送。
- **每月 1 日** — 复盘提醒(季度/半年附加检查项)。
- **git post-commit 钩子** — 涉及报告口径的提交自动重建静态报告页并推送。
